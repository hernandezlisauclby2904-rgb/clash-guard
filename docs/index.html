围绕真正需要核对的几件事

路由未验证时会跳过第三方 IP 查询。请注意：进入 TUN 不代表 Mihomo 一定为某个域名选择代理，规则仍可能是 DIRECT；需要确认预期出口时请设置 expectedIPv4 并检查 Clash 规则。第三方 IP 查询站点会看到实际请求出口，只向你信任的服务发送查询。

⌁

TUN 与代理状态

检查 Clash/Mihomo 进程、TUN 网卡、IPv4/IPv6 默认/分流路由，以及 Windows 系统代理、PAC 和 WPAD 设置。

IPv6 路由检查

区分公网全局 IPv6 与 ULA/链路本地地址，进一步检查活动默认/分流路由。

⌕

多来源 IP 参考

聚合 IP 信息与风险指标。接口失败或数据不足时显示 UNKNOWN，而不是假装通过。

◷

定时巡检

使用 Windows 计划任务周期检查，把状态、异常和修复动作记录到本地日志。

↻

有边界的自动修复

自动修复默认关闭；由用户明确启用后，才在 TUN、IPv4/IPv6 路由与流量验证通过、且确认系统代理全部指向本机时尝试关闭本地代理开关。

⚑

启动检查与应急通道

支持受控启动前检查、进程创建后的响应式监控，以及限时软放行/紧急放行。

Workflow

明确检查、谨慎修复、留下记录

自动修复不是“无条件开关网络”。它必须先满足前置条件，失败时保留原有代理状态并解释原因。

读取本地状态

读取 Clash 进程、TUN 网卡和 Windows 代理配置。

检查风险信号

查看 IPv6 路由、TCP 连通性与 IP 服务返回结果。

分类处理

明确区分 PASS、FAIL、UNKNOWN；未知数据不会伪装成安全。

复检与留档

若执行自动修复，重新检查关键条件，并写入本地日志。

Signal quality

三种状态，不混为一谈

这套分类帮助识别“确实发现问题”和“没有足够证据”的差异。

PASS · 有效检查通过

关键检查具备有效结果，且没有触发配置阈值。它不代表账号一定可用。

FAIL · 检测到违例

例如系统代理仍开启，IPv6 默认路由指向物理网卡，或可信度有限的第三方信号超过阈值。

UNKNOWN · 信息不足

接口超时、响应字段变化或路由信息不完整。按策略可 fail-open，但不会显示成 PASS。

重要安全边界Clash Guard 不是 VPN、不是 Claude 官方产品，也不保证匿名或不被封号。第三方“住宅 IP / 风险分”不是 Anthropic 官方判定。系统路由进入 TUN 不能证明所有 Mihomo 规则都会选代理；某些域名可能被规则设为 DIRECT。第三方 IP 查询站点会看到实际出口地址。Watch 默认监听 `Claude.exe`，通过进程创建事件进行响应式检查，不能等同于 Windows 内核级的启动前封锁，也不保证覆盖 Claude Code CLI；需要启动前校验时，优先使用 `-Launch` 受控启动入口。首次运行前，请先阅读 README 并完成回归测试。
