# Claude / 独立代码审查提示词（Clash Guard 2.0）

你是第二位独立审查者。请审查本文件夹内的完整 Clash Guard 2.0 源码，尤其是 `clash_guard.ps1`、`install.ps1`、`uninstall.ps1`、`toast_action.vbs`、配置、README 和回归测试计划。不要因为现有文档声称已修复就默认相信实现；请从源码重新推导。

## 审查目标

找到会导致真实运行错误、误报/漏报、网络被错误修改、启动门控失效、死锁/重复守护、缓存陈旧、通知按钮失效、安装/卸载破坏用户环境或安全边界被绕过的问题。优先级按实际影响排序，而非格式或命名偏好。

重点逐项检查：

1. Windows PowerShell 5.1 语法、参数绑定、对象数组/单对象退化、`$ErrorActionPreference = 'Stop'` 下的异常路径。
2. IPv4 路由判定是否正确处理默认路由、Clash 的 `0.0.0.0/1` 与 `128.0.0.0/1`、多接口同 metric、缺失路由和读取失败；证据不足时是否明确 UNKNOWN。
3. IPv6 全局地址与 ULA / link-local 区分、默认/分流路由核验、复检路径，以及是否会把 UNKNOWN 误判为 PASS。
4. 第三方 IP JSON 的字段验证、IPv4 地址规范校验、至少两个 IPv4 来源一致、风险数据源去重、IP 变化时缓存失效、外部 HTTP 查询前的路由前置检查。
5. `ProxyEnable`、复合 `ProxyServer`、PAC、WPAD 的判定与自动修复边界；是否可能关掉非本地用户代理或在验证失败后忘记恢复原状态。
6. `-Report` 是否只读；`-Launch` 的受控启动；`-Watch` 的进程创建事件竞态、PID 重用/子进程树行为、异常时 fail-closed；应急放行和停止/恢复语义。
7. 计划任务触发器/账户/权限、旧任务迁移、防止双守护；路径包含空格、括号、方括号和非 ASCII 字符的表现。
8. Toast protocol 注册、URI 白名单、VBS 参数引用、重复注册、移动目录后更新；不应存在任意参数注入。
9. 日志和 JSON 状态写入的并发/原子性；日志不得意外泄漏 API secret。
10. README、发布文案、landing HTML 是否与真实实现一致；不得宣称百分百防泄露、不会封号、毫秒级启动前拦截或已完成未执行的测试。

## 输出格式

按以下结构给出审查报告：

- **阻断级问题**：只有会导致安全边界被绕过、严重错误改网或程序无法运行的问题才放入此项。
- **高优先级问题**：明确的逻辑错误、可靠性缺陷或关键兼容性问题。
- **中低优先级问题**：有证据的边界问题与维护性风险。
- **无问题但需实机验证的项目**：说明为什么仅凭静态阅读不能下结论。
- **最小修改建议**：对每个问题列文件、函数/行附近、触发条件、实际影响、建议改法和回归测试。

每条必须包含源码证据。不要臆测代码执行结果，也不要声称运行过 Windows、Clash 或 Toast 除非你真的在该环境执行。不要直接修改文件；先交付审查结果，方便主实现者吸收再修复。
